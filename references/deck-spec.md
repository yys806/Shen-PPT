# deck-spec.json 内容单源规范（v1.0）

**核心原则**：内容只写一遍（deck-spec），HTML/PPTX 两管道共用。渲染引擎只读 spec + style-spec + skeleton，不做内容决策。

## 顶层字段

```json
{
  "deckTitle": "标题",
  "subtitle": "副标题（可省略）",
  "author": "禹尧珅",
  "affiliation": "同济大学 电子与信息工程学院",
  "date": "2026-08-13",
  "scenario": "s1-pku | s2-course | s3-thesis | s4-html",
  "style": "pku-report",
  "sections": [
    {"id": "1", "title": "研究背景", "short": "背景"},
    {"id": "2", "title": "方法设计", "short": "方法"}
  ],
  "slides": [ ... ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| deckTitle | ✅ | 主标题 |
| scenario | ✅ | 决定渲染管线（S1-S4） |
| style | ✅ | 风格名，须在 styles/index.json 注册 |
| sections | ✅（S2/S3 必填） | 章节表；`short` ≤4 字（目录/章节条显示用） |
| slides | ✅ | 页面数组，见下 |

## slide 类型与字段

### cover 封面
```json
{"type": "cover", "title": "可选覆盖deckTitle", "subtitle": "", "author": "", "date": ""}
```
缺省字段自动取顶层值。

### toc 目录
```json
{"type": "toc", "title": "目录"}
```
目录项默认从 `sections[]` 自动生成（编号 + title）。也可显式 `{"items": ["1 研究背景", "2 方法设计", "..."]}` 覆盖。

### section 章节页
```json
{"type": "section", "section": "1", "title": "研究背景", "tagline": "一句话概述"}
```
`section` 引用 sections[].id，自动渲染大章节号。

### content 内容页（S2/S3 必带 section）
```json
{
  "type": "content",
  "section": "2",
  "layout": "bullets",
  "title": "本页标题",
  "body": ["要点1", "要点2", "要点3"],
  "image": "images/fig1.png",
  "caption": "图注",
  "notes": "演讲备注（讲稿用）"
}
```

| layout | 布局 | body 语义 | 可用附加字段 |
|---|---|---|---|
| `text` | 单栏正文 | 段落数组（每元素一段） | image, caption |
| `bullets` | 单栏要点 | 要点数组（**原生项目符号**，见下） | image, caption |
| `image-right` | 左文右图 | 要点数组 | **image 必填**, caption |
| `image-left` | 左图右文 | 要点数组 | **image 必填**, caption |
| `two-col` | 双栏 | `{"left": [...], "right": [...]}` | — |
| `table` | 表格 | `{"headers": ["列1","列2"], "rows": [["a","b"]]}` | — |
| `stats` | KPI 数字 | `[{"num": "87%", "label": "准确率"}, ...]` | — |

**⚠️ 修改 spec 时跳过 table/stats/two-col 的 dict body**（按列表遍历会把它拆成键列表，曾两次踩坑）。

### body 层级标记语法（bullets 布局）

```json
"body": [
  "# 一级标题",            // 原生项目符号：模板 Wingdings □ 红，lvl 0，文字黑加粗
  "## 小标题：说明文字",    // ◆ 蓝 lvl 1；冒号前小标题自动蓝色加粗，冒号后黑色不加粗
  "### 三级标题",           // ➢ 蓝 lvl 2；同样支持冒号前蓝加粗
  "正文段落",              // 无符号 lvl 3，黑色不加粗
  "**重点词**"              // 红色加粗重点关键词（只标词，不标整句）
]
```

- `#`/`##`/`###` 前缀 = 一/二/三级（**原生 PowerPoint 大纲级别**，渲染后回车自动延续层级与符号）
- 冒号（：或:）前短语 **≤24 字**自动**蓝色加粗**（小标题），冒号后黑色不加粗（说明文字）
- `**关键词**` = **红色加粗**（只标关键词，不要整句加粗）
- 具体符号/颜色/缩进参数来自风格库 bullets 配置（直接抄单位模板 XML，见 `template-specs.md`）

### 参考文献与上标引用（铁律）

content 页可带 `references` 字段（**每页从 [1] 独立编号**）：

```json
{
  "type": "content",
  "title": "Renderer 技术演进",
  "body": ["### **Diffusion Forcing**[1]：兼顾全局序列一致性", "..."],
  "references": [
    "[1] B. Chen, et al. \"Diffusion Forcing.\" NeurIPS, 2024.",
    "[2] W. Yan, et al. \"VideoGPT.\" 2021."
  ]
}
```

规则（用户多次强调，不可违背）：
1. **正文引用 = 上标**：`[n]` 渲染为 superscript（引擎 baseline=+30000；**OOXML 正值=上标、负值=下标**）
2. **引用紧跟文献名称**（`TDMPC2[1]`、`Sora[3]`），**绝不引句末**
3. **每页从 [1] 重新编号**；同一页同一文献同名同号
4. **只有该页正文实际引用（文献名称出现）才写 references**；无引用页不写文献、不加引用
5. 正文引用编号 ⊆ 该页 references 编号（引擎校验）
6. 参考文献框：左下角贴页面角（x=0、底=720），9pt 灰 #595959，一行一条，**不上标**
7. 正文与文献重叠 → 引擎自动正文上移 + 左右拉长

### ending 结束页
```json
{"type": "ending", "title": "谢谢聆听", "thanks": "恳请各位老师批评指正", "contact": "yys806@tongji.edu.cn"}
```

## 其他约定

- **图片路径**：相对 spec 文件所在目录（如 `images/fig1.png`）；规格建议 ≥1600px 宽，总大小控制 10MB 内
- **章节归属硬规则**：S2/S3 所有 content/section 页必须写 `section`；渲染时 sectionTag 区域自动显示 `章节号·章节名`
- **文本密度**：正文每页 ≤6 要点或 ≤4 段；超出拆页（对齐"低密度/演讲型"默认）
- **备注**：`notes` 写讲述要点（3-5 条提词卡式），不写逐字稿；交付时转成讲稿.md

## 校验

渲染引擎启动时自动检查：scenario/style 合法、sections 引用完整、S2/S3 content 页都有 section。违反即报错退出，不渲染残缺 deck。

## 附录：大纲预览模板（Step 3 必做）

动手写 spec 前输出此 MD 大纲给用户确认。**用户确认后才能写 spec / 渲染。**

### S1 组会版（无目录/章节页，不选风格）

```markdown
# 《标题》组会汇报 · 大纲预览
- 场景：S1 北大组会 | 风格：pku-report（锁定，不选）
- 日期：XXXX-XX-XX | 汇报人：禹尧珅
- 封面摘要：
  1. 要点一
  2. 要点二
  3. 要点三

## 页面规划（N 页）
| # | 页类型 | 标题 | 内容要点 |
|---|--------|------|----------|
| 1 | 封面 | 《标题》 | 副标题+摘要 |
| 2 | 内容 | 研究进展 | □ 一级点 / ◆ 二级点 / ➢ 三级点 |
| 3 | 内容 | 实验与问题 | ... |
| 4 | 结束 | 谢谢 | 致谢语 |
```

### S2/S3 答辩版（封面+目录+章节页+每页章节归属）

```markdown
# 《标题》答辩 · 大纲预览
- 场景：S3 论文答辩（或 S2 课程答辩）| 风格：待选（预览后定）
- 日期：XXXX-XX-XX | 答辩人：禹尧珅

## 章节结构
1. 研究背景（背景）
2. 方法设计（方法）
3. 实验验证（实验）
4. 总结展望（总结）

## 页面规划（N 页）
| # | 页类型 | 章节 | 标题 | 内容要点 |
|---|--------|------|------|----------|
| 1 | 封面 | — | 《标题》 | 副标题+答辩信息 |
| 2 | 目录 | — | 目录 | 四章节列表 |
| 3 | 章节页 | 背景 | 研究背景与动机 | 一句话概述 |
| 4 | 内容 | 背景 | 研究背景 | 要点... |
| 5 | 内容 | 方法 | 整体架构 | ... |
| 6 | 内容 | 实验 | 主要结果 | 表格/数据... |
| 7 | 结束 | — | 谢谢聆听 | 致谢语+联系方式 |
```

**输出规则**：
- 大纲只做信息规划，不做视觉设计（视觉属于风格预览阶段）
- S1 大纲**不得**出现目录/章节页；S2/S3 大纲每页必须带章节归属
- 用户改大纲 → 更新大纲 → 再进入风格/渲染阶段
